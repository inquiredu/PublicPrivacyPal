## What is inherited, improved, or deliberately different

The original already has deterministic scoring, human corrections/overrides, public/staff projection
helpers, source-quality cues, unresolved-criterion views, input freshness checks, keyboard tabs and
focus-managed dialogs. Do not describe those concepts as inventions of this rewrite. The advances
below are specific strengthened contracts, additional controls or locally demonstrated workflows.
Missing features and disabled integrations are not improvements in product completeness.

## Suggested backport order and record template

Start with a source-only proposal for publication correctness, draft protection and validation UX;
review server receipt/authorization dependencies at the same time. Server job isolation and strict
boundaries deserve early design attention but are larger changes than a component transplant.
Storage/evaluation migrations, source coverage and segmented assistance follow only with compatible
readers and a recovery design. Priorities express potential value, not permission or completion.

For each candidate retain:

- [ ] Original source/deployment version actually assessed; affected original files and failure case.
- [ ] Public implementation commit, tests, recorded browser evidence and precise remaining limitations.
- [ ] Intended user behavior, dependencies and smallest reviewable patch; no district data in fixtures.
- [ ] Compatibility/migration, rollback and data-retention plan where relevant.
- [ ] Synthetic failure-injection and authorization results on the proposed original-project patch.
- [ ] Separate owner authorization before changing the original repository or deployment.

The owner excluded DPA document generation/signing/vendor upload/delivery from parity restoration
on October 22. Existing manual agreement status/reference/date/scope remains a separate review fact.
No DPA automation is recommended for backport by this register.

integration tests, schema-9 fixture import and two schema-10 recovery cycles. This register and
parity checklist are documentation-only; those suites were not rerun and no original patch was made.
